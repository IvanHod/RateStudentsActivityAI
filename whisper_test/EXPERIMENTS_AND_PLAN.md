# Распознавание лекций: журнал экспериментов и план

Статус: 8 октября 2026. Этот файл — единая точка входа в результаты для
размеченного фрагмента `chunk_0049` (54 эталонных слова). Подробные CSV, полные
транскрипции и выравнивания лежат в соответствующих папках `v1`–`v11`.

## Как читать результаты

- **WER** — доля ошибок на уровне слов; основной критерий выбора.
- **CER** — доля ошибок на уровне символов; помогает увидеть близкие по
  звучанию искажения.
- У разных версий могли отличаться модель, VAD и набор сравниваемых WAV.
  Поэтому напрямую сопоставимы прежде всего строки с одинаковыми условиями.
- Текущий лучший воспроизводимый результат: **Whisper medium +
  `target_voice_focus` + VAD `0.5 / 100 / 500 / 200` = WER 27.78%,
  CER 16.94%**.

## Зафиксированные факты

1. Качество аудио существенно влияет на WER: на одинаковом фрагменте
   предобработка меняла результат от примерно 28% до более 80% WER.
2. Агрессивные фильтры не являются универсальным улучшением. `loudnorm`,
   сильная полосовая фильтрация и часть шумоподавляющих обработок вызывают
   вставки, повторы или теряют речь.
3. VAD нужен, но его параметры зависят от типа входа. Текущий общий профиль
   проверен лучше остальных только на `chunk_0049`.
4. Проблемная фраза «Смотрите, неявное преобразование типов» остаётся
   нестабильной. Модели часто распознают «неявное преобразование», но теряют
   или искажают «типов»; человек восстанавливает фразу благодаря слуху и
   предметному контексту.
5. Смена ASR-модели сама по себе не решила проблему: Whisper medium остаётся
   базовым лидером. Значит, следующий приоритет — сохранить больше полезного
   сигнала и корректно подать его модели, а не перебирать модели вслепую.

## План следующих экспериментов

### Подготовительный этап: сделать выводы переносимыми

**Цель:** не оптимизировать настройки только под один удачный 60-секундный
фрагмент.

1. Разметить ещё 3–5 фрагментов по 30–90 секунд: с тихой речью, шумом
   аудитории, вопросами студентов и обычной лекционной речью.
2. Для каждого сохранить точный эталон и отметить предметные термины, включая
   «неявное преобразование типов», `int`, `var`, «компилятор».
3. В отчёте считать общий WER/CER, WER по терминам и количество вставок.

**Критерий готовности:** каждый следующий эксперимент запускается на всём
наборе, а не только на `chunk_0049`.

### v12: VAD без склейки речи встык

**Гипотеза:** текущая склейка VAD-сегментов удаляет естественные паузы и может
ухудшать границы реплик и языковой контекст Whisper.

- Для исходника и пяти текущих лидеров распознавать каждый VAD-сегмент
  отдельно, сохраняя 200–400 мс padding.
- Склеивать только готовые транскрипции в хронологическом порядке.
- Сравнить с текущей склейкой на Whisper medium; не менять одновременно WAV,
  модель и параметры VAD.

**Успех:** средний WER меньше baseline хотя бы на 2 п.п., а число вставок не
растёт; проблемная фраза не теряет больше слов.

### v13: локальная проверка проблемной фразы

**Гипотеза:** качество падает в небольшой зоне записи, поэтому параметры,
полезные для всей минуты, маскируют потенциально полезную обработку.

- Вырезать окно примерно 5 секунд до и после фразы «Смотрите, неявное
  преобразование типов» из исходного видео без дополнительного AAC.
- Подготовить небольшую контролируемую сетку: исходный левый канал, L/R 60/40,
  `target_voice_focus`, мягкое speech enhancement и их комбинации.
- Не использовать normalisation, compressor или жёсткий band-pass: они уже
  ухудшили полный фрагмент.
- Оценивать вручную по эталону этой фразы и автоматически по WER короткого
  окна, затем подтвердить лучший рецепт на остальных фрагментах из набора.

**Успех:** полностью восстановлена фраза без подмены близкими словами и нет
ухудшения среднего WER полного фрагмента.

### v14: разделение целевого голоса / speech enhancement

**Гипотеза:** основные ошибки вызваны конкурирующими голосами и акустикой
аудитории, а не просто уровнем громкости.

- Протестировать один алгоритм enhancement и один алгоритм separation,
  каждый отдельно от имеющегося `target_voice_focus`.
- Если доступна чистая короткая реплика лектора, использовать её только как
  reference voice для выделения говорящего; без такой записи не заявлять
  target-speaker separation.
- Сначала проверять на `chunk_0049` и двух контрастных фрагментах, затем — на
  полном наборе при наличии улучшения.

**Успех:** улучшение среднего WER минимум на 2 п.п. на нескольких фрагментах.
Если улучшен лишь один фрагмент, обработка остаётся экспериментальной.

### v15: контекстная коррекция с прозрачным журналом

**Гипотеза:** часть оставшихся ошибок — устойчивые фонетически близкие замены
предметных терминов, которые можно корректировать после ASR.

- Сформировать небольшой словарь терминов курса и разрешить замену только при
  высокой фонетической/строковой близости к одному термину.
- Хранить рядом три поля: исходная транскрипция ASR, исправленный текст и
  список применённых замен с причиной.
- Сравнить: без коррекции, короткий Whisper prompt и посткоррекцию. Не
  применять длинный prompt — v1 показал его повторение.

**Успех:** растёт точность терминов, а ручная проверка не находит ложных
«исправлений». Этот слой должен быть опциональным, а не скрывать исходный
текст модели.

### v16: модели и ансамбль только после улучшения сигнала

**Гипотеза:** разные модели могут дополнять друг друга на уже отобранном
сильном аудио, но не заменят качественный вход.

- Выбрать из `models_testing.md` ещё одну релевантную модель и запускать её на
  неизменном наборе: оригинал плюс пять текущих вариантов.
- Проверить ensemble только там, где модели расходятся: не выбирать текст по
  интуиции, а использовать заранее определённое правило и оценку WER.
- Сопоставлять с Whisper medium baseline и учитывать скорость, память и
  сложность развёртывания.

**Успех:** средний WER ниже Whisper baseline на независимых фрагментах.

## Правила принятия решения

1. Изменять за один эксперимент одну переменную: аудио, VAD, модель или
   посткоррекцию.
2. Сохранять команду запуска, исходный набор WAV, версию модели и все параметры
   в README соответствующей версии.
3. Не включать обработку в основной конвейер по улучшению только одного
   фрагмента.
4. Основной baseline до появления устойчивого победителя: **Whisper medium +
   `target_voice_focus` + VAD `0.5 / 100 / 500 / 200`**.
