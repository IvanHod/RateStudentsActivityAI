# StudentScoreAI

Сервис находит упоминания студентов в записях лекций, сверяет их с официальным
списком и готовит безопасные корректировки баллов в Google Sheets.

Текущая политика — **v5**: автоматическое начисление отключено, пока результаты
не пройдут review. Балл начисляется для совпадения с `confidence > 30` — порог
строгий, поэтому значение `30` само по себе не подходит.

## Подготовка

Нужны Python 3.12, [uv](https://docs.astral.sh/uv/) и `make`.

```bash
uv sync
make help
```

Создайте `.env` и задайте обязательные параметры:

```dotenv
LITELLM_API_KEY=...
LITELLM_BASE_URL=https://...
SPREADSHEET_ID_2026=...
GOOGLE_SERVICE_ACCOUNT_FILE=/полный/путь/к/service-account.json
```

Необязательные параметры и их значения по умолчанию:

```dotenv
WORKSHEET_NAME_2026=Семестр II
POINTS_PER_MENTION=0.5
STUDENT_START_ROW=4
```

У сервисного аккаунта должен быть доступ редактора к целевой Google Sheets.
Ссылка на публичную папку Яндекс Диска задаётся в `student_score_ai/main.py`.

## Основные команды

```bash
# Обработать все лекции из публичной папки.
make run_all

# Обработать все лекции недели. Подойдёт любая дата этой недели.
make run_week 07.10.2026

# Эквивалентный стандартный синтаксис make.
make run_week DATE=07.10.2026

# Обработать ровно один файл; имя должно в точности совпадать с именем на Диске.
make run_lecture LECTURE="Лекция1_3основы_С_поток1_21.09.2026.mp4"

# Полное восстановление после ручной очистки всех баллов в таблице.
make score_rebuild_preview_all
make score_rebuild_all CONFIRM=REBUILD
```

`run_week` выбирает даты с понедельника по воскресенье недели, в которую входит
указанная дата. Команды обработки используют кэш аудио, транскриптов и найденных
ФИО, поэтому не скачивают и не распознают видео повторно, если нужные артефакты
уже есть.

## Рекомендуемый рабочий процесс

### 1. Создать результаты валидации

```bash
make run_all
```

Для каждой лекции появятся `fio_list_v6.json` и `students_validated_v6.json`.
v6 сохраняет не только полные ФИО, но и искажённые идентификационные фрагменты
из транскрипта вместе с их контекстом. Для каждого неточного фрагмента она
строит несколько кандидатов из реестра и проверяет их по контексту. Это
позволяет обработать случаи вроде неверно произнесённой, склеенной или неверно
распознанной фамилии без подбора студента вне реестра.

Автоматических записей в Google Sheets на этом этапе нет.

### 2. Построить локальный план корректировок

```bash
make score_preview_all
```

Команда создаёт `sheet_updates_v5_preview.json` для каждой v5-лекции. План
сравнивает желаемые упоминания v5 с историей предыдущих начислений в
`completed.json` и с уже применёнными ручными корректировками. Дельта может
быть как положительной, так и отрицательной.

Эта команда **не читает и не изменяет Google Sheets**.

### 3. Сверить план с текущими ячейками Google Sheets

```bash
make score_compare_sheet_all
```

Команда читает Google Sheets без записи и для каждой корректировки выводит:

```text
Студент: сейчас 1, корректировка -0.5, станет 0.5
```

При этом локальный preview может быть обновлён. Текущая ячейка может содержать
баллы других лекций той же недели или ручные правки. Поэтому команда показывает
эффект рассчитанной дельты, но не считает
текущее число в таблице ошибочным сама по себе.

### 4. Применить проверенные корректировки

```bash
make score_apply_all CONFIRM=APPLY
```

Это единственная команда, которая записывает изменения в Google Sheets. Перед
записью она создаёт `pending`-запись в `score_application_ledger.json`, а после
успеха меняет её на `applied`. Это защищает от случайного повторного начисления.

Если команда прервалась и в журнале остался статус `pending`, не запускайте её
повторно вслепую: сначала проверьте фактические ячейки через
`make score_compare_sheet_all`.

### Полное восстановление после очистки таблицы

Если все начисления сервиса были вручную удалены из Google Sheets, **не**
используйте `score_apply_all`: он рассчитывает только разницу относительно
старой истории. Сначала убедитесь, что v5 создана для всех лекций:

```bash
make run_all
make score_rebuild_preview_all
```

`score_rebuild_preview_all` показывает все подходящие упоминания v5 без
вычитания старых начислений. После проверки выполните ровно один раз:

```bash
make score_rebuild_all CONFIRM=REBUILD
```

Команда восстановит полные баллы для всех найденных результатов v5 и создаст
`score_rebuild_baseline.json` в каждой папке лекции. Эта точка становится новой
локальной историей для следующих версий. Повторный полный запуск блокируется,
чтобы не начислить баллы дважды.

## Версии и артефакты

Не перезаписывайте результаты предыдущей версии. При изменении логики увеличьте
`version` в `student_score_ai/validation_policy.py`; следующая обработка создаст
новые файлы вида `students_validated_vN.json` и отдельное сравнение версий.

В рабочей папке лекции важны следующие файлы:

| Файл | Назначение |
| --- | --- |
| `fio_list_vN.json` | Извлечённые ФИО или искажённые фрагменты, минуты и контекст версии `N`. |
| `students_validated_vN.json` | Решения алгоритма валидации версии `N`. |
| `students_validation_comparison_vN.json` | Построчное сравнение доступных версий. |
| `completed.json` | История начислений предыдущего обычного запуска. |
| `sheet_updates_vN_preview.json` | Локальный план корректировок текущей версии. |
| `score_application_ledger.json` | Защищённый журнал уже применённых ручных корректировок. |
| `score_rebuild_baseline.json` | Новая точка отсчёта после полного восстановления очищенной таблицы. |

Не удаляйте `completed.json` или `score_application_ledger.json`, если нужно
сохранить корректный расчёт дельты. Новую проверку следует запускать новой
версией политики, а не удалением старых файлов.

## Безопасность начислений

- Всегда выполняйте `score_preview_all` и `score_compare_sheet_all` до `score_apply_all`.
- `score_apply_all` поддерживает как добавление, так и вычитание баллов.
- Корректировка, которая привела бы к отрицательному баллу, останавливается с ошибкой.
- Повторное применение одной версии для одной лекции блокируется журналом.
- Команды `run_*` в текущем review-режиме не начисляют баллы автоматически.
